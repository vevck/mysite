Executive Summary

Newport-Pleasure.com is a consumer-facing, age-gated cigarette brand website built on Adobe Experience Manager (AEM Sites). The site serves as a brand engagement hub, loyalty rewards platform, digital coupon delivery system, and content lounge for adult smokers (21+). It is operated by R.J. Reynolds Tobacco Company and features a comprehensive MarTech stack (20+ integrations), a Loyalty Plus rewards program with gamification, user-generated content features (UGC photo contests), and rich interactive content (polls, quizzes, comments).

Section 5 – Complex Use Cases & Observations

5.1 Age-Gated Authentication System

Regulatory Requirement: Federal law requires age verification (21+) for all tobacco brand websites. This is non-negotiable and must be implemented in the EDS migration.
  • Current implementation: All content lives under /secure/ path. Public-facing pages limited to login, registration, forgot-password, and legal documents.
  • Login flow: Email + password authentication, session token management, age verification at registration.
  • Registration: Multi-step form with age verification, state selection, identity verification, hCaptcha bot protection. Imperva WAF provides additional security layer.
  • EDS challenge: EDS serves content from CDN (Fastly). Authentication must be implemented as client-side JavaScript gate or custom worker/middleware to protect all /secure/ content. Token validation against api.newport-pleasure.com must happen before content rendering.

5.2 Loyalty Plus Rewards & Pack Code Scanning

  • Core feature: Users scan cigarette pack barcodes/QR codes using mobile camera to earn rewards points.
  • Components involved: Code Entry widget (camera + manual input), points balance display, rewards catalog, earning history, step-by-step onboarding guide.
  • Technical complexity: Camera API access (getUserMedia), barcode scanning library, real-time API validation, points crediting, error handling for invalid/duplicate codes.
  • EDS challenge: Loyalty Plus SDK is currently an AEM clientlib. Must be extracted, potentially refactored, and loaded as an EDS block dependency. Camera scanning requires secure context (HTTPS) and user permission handling.

5.3 User-Generated Content (Pleasure POV)

  • Feature: Photo contest where users upload photos that go through moderation and appear in a public voting gallery.
  • Workflow: Photo capture/selection → Crop/filter → Caption → Submit → Moderation queue → Published → Voting/likes → Featured winners.
  • Technical complexity: File upload to API, image processing/resizing, content moderation workflow (API-driven), gallery rendering with lazy loading, voting system with rate limiting.
  • EDS challenge: This is the most complex single feature. Requires custom block with multi-step upload flow, API integration for all CRUD operations, and real-time gallery updates. Consider implementing as a dedicated web component or embedding a micro-frontend.

5.4 Gamification & Social Engagement Engine

  • Features: Polls with image/text options, comments with threading, likes with counts, points badges on activities, share functionality.
  • Points economy: Users earn points for: viewing content, completing polls, posting comments, watching videos, uploading photos. Points displayed as badges ("+50 pts") on content cards.
  • Technical complexity: Real-time engagement counters (likes, comments), poll state management (voted/not voted), comment moderation, points crediting via API, social share deep-links.
  • EDS challenge: Multiple interactive blocks that share state (user points, engagement history). Requires centralized state management approach in EDS (likely a shared JavaScript module) and consistent API integration patterns.

5.5 Digital Coupon System

  • Feature: Personalized digital coupons delivered based on user profile and behavior.
  • Components: Coupon listing with expiration dates, coupon activation workflow, print/digital delivery options, terms per coupon.
  • Technical complexity: Personalized API responses, coupon state management (available/activated/used/expired), notification integration for new coupons.
  • EDS challenge: Fully API-driven, no static content. Block must handle all coupon states and transitions. Integration with notification center for real-time updates.

5.6 Regulatory Compliance

  • Surgeon General's Warning: Must appear on every page. Currently a fixed top banner. Non-negotiable federal requirement.
  • Age verification: 21+ requirement for all content access. Must be maintained in EDS.
  • Privacy compliance: CCPA "Do Not Sell My Info" link, comprehensive privacy policy, cookie consent management.
  • Advertising restrictions: Tobacco advertising regulations affect what content can be shown and how. Marketing claims must comply with FDA guidelines.
  • EDS consideration: Regulatory requirements must be wired into the EDS header/footer fragments and authentication middleware from day one. No content should be accessible without age verification.

5.7 External Redirects & Cross-Brand Architecture

  • Sustainability page: Redirects to an external R.J. Reynolds corporate sustainability page rather than hosting content locally.
  • Shared infrastructure: Newport shares API backend, Loyalty Plus SDK, and authentication system with sibling brands (VELO, VUSE, Camel). This means API changes during Newport migration could affect other brands.
  • EDS consideration: Cross-brand API dependencies must be mapped and tested. Consider creating shared EDS libraries for common functionality (auth, Loyalty Plus, analytics).

5.8 Progressive Web App (PWA) Features

  • Service Worker: Active service worker for offline caching and push notifications.
  • Impact: EDS has its own service worker for performance optimization. Custom service worker logic (push notifications, offline caching) must be carefully merged or replaced.
