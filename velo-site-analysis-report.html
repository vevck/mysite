Executive Summary

VELO.com/us is a consumer-facing, age-gated nicotine pouch brand website built on Adobe Experience Manager (AEM Sites). The site serves as a product showcase, loyalty rewards platform, and engagement hub for adult nicotine consumers (21+). It features a heavy MarTech stack (25+ ad-tech/analytics vendors), a Loyalty Plus rewards program with gamification, Google Maps store locator, and social engagement features (polls, comments, likes).

Key Findings: The site is relatively small in page count (~45–60 pages) but high in interactive complexity. Section 6 – Migration Estimates

6.1 Phase Breakdown

Phase Duration Effort (Person-Days) Details
Phase 1: Infrastructure & Design System 3–4 weeks 15–20 days EDS project setup, Velo WWangle font integration, global styles (CSS custom properties), nicotine warning banner, global header with notification system, hamburger menu, global footer, safety information bar. Custom delayed.js for 25+ ad-tech pixels.
Phase 2: Authentication & API Layer 4–6 weeks 20–30 days Age-gated authentication proxy/middleware, session management, usapi.velo.com API integration, MFA for profile, registration multi-step wizard, forgot password flow. This is the highest-risk phase — EDS has no native auth support.
Phase 3: Core Block Development 4–5 weeks 20–25 days ~16 EDS blocks (hero variants, product grid, comparison, carousels, FAQ accordion, contact form, video player, store locator teaser, rewards promo, newsletter signup). Includes responsive design and accessibility.
Phase 4: Complex Features 5–7 weeks 25–35 days Google Maps store locator, Loyalty Plus rewards integration, gamification engine (polls, comments, likes, points), mobile coupon system, notification center, personalization (Adobe Target), Experience More content hub with filtering/pagination.
Phase 5: Content Migration 2–3 weeks 10–15 days ~45–60 pages. Automated migration for ~8 legal/informational pages. Semi-automated for ~7 form/product pages. Manual for ~30–45 interactive/dynamic pages. Image asset migration.
Phase 6: Integration Testing 2–3 weeks 10–15 days Analytics validation (Adobe Analytics, Target, AAM), ad-tech pixel verification (25+ vendors), loyalty program end-to-end testing, store locator API testing, form submission testing, MFA flow validation, coupon redemption testing.
Phase 7: QA, Compliance & UAT 3–4 weeks 15–20 days Cross-browser testing, mobile responsiveness, accessibility (WCAG 2.1 AA), FDA regulatory compliance check (warning labels, age verification), state privacy rights compliance, TCPA compliance for SMS, performance optimization (Lighthouse 100 target), UAT with stakeholders.
Phase 8: Go-Live & Monitoring 1–2 weeks 5–10 days DNS cutover, redirect mapping, production monitoring, post-launch analytics validation, hotfix period.
TOTAL 24–34 weeks 120–170 person-days Approximately 6–8 months with a team of 3–4 developers

6.4 Risk Factors

Risk Impact Likelihood Mitigation
Authentication architecture on EDS High High EDS has no native auth. Requires edge worker/middleware or CDN-level auth proxy. Prototype early. Consider hybrid approach (EDS for public pages, existing AEM for authenticated).
Loyalty Plus SDK compatibility High Medium Custom AEM clientlib SDK needs refactoring for EDS. Engage Loyalty Plus team early. May require API-only integration approach.
Regulatory compliance gap High Medium FDA tobacco marketing regulations are strict. Ensure all warning labels, age gates, and state-specific disclaimers are pixel-perfect. Legal review required before launch.
Ad-tech pixel performance impact Medium High 25+ pixels will impact page load. Load all via delayed.js. Audit each pixel for necessity. Consider server-side tag management.
Gamification engine complexity Medium Medium Polls, comments, likes, and points require real-time API. Consider phased rollout: launch without gamification, add in phase 2.
Google Maps API cost Low Low Maps API usage may increase with EDS traffic changes. Monitor API call volumes.
