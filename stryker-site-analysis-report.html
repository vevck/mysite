Key Finding: Stryker.com is built on Adobe Experience Manager (AEM) Sites with Scene7/Dynamic Media for image delivery. The site is a large-scale medical technology corporate website covering 19 business divisions, 3 major portfolios (MedSurg, Orthopaedics, Neurotechnology), 488+ news articles, and a deep product catalog. The site already uses Adobe Helix RUM (Real User Monitoring from Edge Delivery Services), indicating EDS migration planning is underway. The site is publicly accessible with no authentication gating, which simplifies migration significantly compared to auth-gated sites.

CMS Platform: Adobe Experience Manager (AEM Sites), evidenced by aem-Grid layout classes, /etc/designs/stryker/clientlibs-* client library paths, /libs/granite/ framework, and Scene7/Dynamic Media integration via media-assets.stryker.com.

Architecture Notes: AEM Templates include tier1-landing, portfolio, base, and tier1-landing-contact. jQuery is loaded twice (Granite + Foundation versions). Seven Scene7 viewer scripts are loaded globally. Multi-region content management supports 74 locales via hreflang tags.

2.3 Block Reuse & Code Footprint Reduction Strategy

Reuse Opportunity: The 22 identified components can be consolidated into ~12 EDS blocks by treating visual variations as design variants of shared content models:
  • Hero block → covers: Hero Carousel (#5), Corporate Responsibility Carousel (#15), Careers CTA Banner (#14)
  • Cards block → covers: News Card Grid (#6), Product Category Card Grid (#7), Feature Card Grid (#17), Awards Badge Grid (#12), Values (#11)
  • Columns block → covers: 50/50 Content + Image (#9), Product Spotlight (#16), Quick Links Grid (#13)
  • Tabs block → covers: Our Focus Tabbed Panels (#8), Tab Navigation (#20)
  • Accordion block → covers: Regional Accordion (#19)
  • Standalone blocks: Infographic/Stats (#10), Statistical Callout (#18), Blockquote (#21), Google Maps (#22)
  • Global: Header (#1), Footer (#2), Cookie Consent (#3), Regulatory Footer (#4)
This reduces the effective code footprint by ~45% compared to building each component as a separate block.

6.3 Key Risks & Blockers

  • Multi-locale scope explosion: 74 locales could multiply migration effort 10–50x depending on content overlap. Prioritize en-US first, then assess locale-specific content vs. shared master copies.
  • Dynamic Media dependency: All images use Scene7 with dynamic presets. Need a clear asset migration strategy — either maintain Dynamic Media URLs externally or re-host all assets in EDS DAM.
  • News listing page with 488+ articles: EDS has no native dynamic listing/filter capability. Requires spreadsheet-driven approach or custom JavaScript block for category filtering and pagination.
  • Search infrastructure: Current AEM search must be replaced. Options include custom search index, Algolia, or Google Programmable Search. Scope depends on search quality requirements.
  • Regulatory compliance: Medical device content carries literature tracking numbers and approval dates. Content changes may require regulatory approval workflows not natively supported by EDS authoring.
  • Licensed fonts: Futura and Humanist Slab fonts are licensed via Fonts.com (Monotype). License must be maintained or fonts replaced. Custom Stryker icon font must be converted to SVG icons.
  • External portal dependencies: careers.stryker.com, investors.stryker.com, patients.stryker.com, strykerivs.com, somesignssavelives.com are external applications that must continue functioning.
  • Marketo form integration: Contact forms likely powered by Marketo (Munchkin ID 338-WAP-571). Form handling must be preserved or replaced with EDS-compatible form solution.
